## 1. What this document is for

The churn tables answer the question **“do vehicles stay in the same
part of the country, and does that differ by age, mileage, fuel or
engine size?”** There are 73 CSV files in `outputs/tables/churn/`. This
document explains, for each one:

- which vehicles are counted (and which are left out),
- which variables were used, how they were grouped, and what was
  calculated,
- what every column means,
- how complete the underlying variables are, and how their values are
  spread,
- the traps worth knowing about before quoting a number.

No programming knowledge is assumed. Where a rule is fussy, the fussy
version is given rather than a simplified one, because the simplified
version is where mistakes come from. Column and file names appear
`like this`.

## 2. The short version

- Every table is built from **one intermediate file**,
  `outputs/intermediate/churn_base.parquet`, which has **one row per
  vehicle** (81,112,156 vehicles) and one column per year for location
  and mileage.
- A vehicle’s location in a year is a **postcode area** (“LS”, “BS”,
  “BT”), or one of three words standing in for “no location recorded”:
  `unborn`, `dead`, `unknown`.
- Almost every table counts vehicles **grouped by postcode area**, and
  splits them either by year or by a characteristic (age, mileage, fuel,
  engine size, emissions category).
- The biggest limitation is not missing data in the usual sense: it is
  what a “location” is. The annualisation gives a vehicle a postcode
  area in every year from its first registration to two years after its
  last MOT: the years before the first MOT (at age three) copy the first
  test’s area, and the two years after the last one carry it on. So a
  vehicle’s area in a year is not always a year in which it was tested
  there, and a scrapped vehicle stays in its area’s stock for about two
  years (section 5 and section 12). In 2019, the best covered year,
  52.3% of the churn-base vehicles had a postcode area.
- The pipeline cross-checks every count that two tables should agree on
  (`outputs/quality/cross_checks.csv`, summarised in the data quality
  report): the Set 2 stock, Set 1b, Set 1d, Set 3, Set 4, Set 7A, 7B and
  7C totals all reconcile with the churn base.

## 3. Where the data comes from

### 3.1 The chain of files

The churn tables are the last step of a longer pipeline. Each step
writes a file; the next step reads it. Nothing in the churn step goes
back to the original data.

| Step | File | What it is |
|----|----|----|
| Input | `annualised_with_ves_4.parquet` | The vehicle-level annualised MOT table supplied to the project, one row per vehicle, with DVLA (VES) columns attached |
| Stage 1 | `outputs/intermediate/01_core.parquet` | The input narrowed to the columns used, typed, with vehicles outside the scope removed |
| Stage 2-3 | `outputs/vehicles_enhanced_maximal.parquet` | Cleaned make/model, harmonised fuel, engine size, Euro status and so on (93,352,241 vehicles) |
| Churn | `outputs/intermediate/churn_base.parquet` | One row per vehicle with the churn measures precomputed (81,112,156 vehicles) |
| Churn | `outputs/tables/churn/*.csv` | The 73 published tables |

“Scope” means a vehicle is kept if it has any recorded mileage, or any
recorded postcode area, or was born on or after 2005-01-01, or shows
DVLA activity (tax, V5C, MOT expiry or first registration) since that
date.

## 4. The one table everything is built from

`churn_base.parquet` has one row per vehicle. Three kinds of column:

1.  **Identifiers and dates** copied or derived from the cleaned file.
2.  **Year columns**: one `pca_YYYY` (location) and one `mileage_YYYY`
    (miles driven that year) per year, 41 columns in all.
3.  **Precomputed measures**: age, move counts, movement rates, bands,
    flags. These are computed once here so that every table uses an
    identical definition. If two tables disagree, it is not because they
    measured differently.

## 5. The vocabulary, pedantically

**Postcode area (PCA)** - the letters at the start of a UK postcode:
“BS” for Bristol, “LS” for Leeds. There are about 120 of them. Northern
Ireland is the single area `BT` (earlier deliveries called it `NI`).

**A real postcode area** - any value that is not `unborn`, `dead` or
`unknown`. The phrase is used throughout: “vehicles in a real PCA in
2017” means vehicles whose location in 2017 was actually known.

**`unborn` / `dead` / `unknown`** - filled in where no postcode area was
recorded, by these rules, in this order:

1.  `unborn` if the vehicle’s `birth_date` year is later than the year
    in question;
2.  `dead` if the vehicle’s last MOT year is earlier than the year in
    question;
3.  `unknown` otherwise - alive, but not observed.

A vehicle with no dates at all is treated as already born.

**Status in a comparison** - when a table compares a vehicle’s location
in one year against a reference year, the answer is one of four words,
tested in this order:

| Status | Meaning |
|----|----|
| `dead` | the comparison year says `dead` |
| `unborn` | the comparison year says `unborn` |
| `same` | a real postcode area, the same as the reference year |
| `different` | **anything else**: a genuinely different area, **or** `unknown`, **or** - where the reference year is the earlier one (Sets 1b, 1c) - a reference-year status of `unborn`, `unknown` or `dead` |

The last row is the single most important caveat in this document.
`different` means “not demonstrably in the same place”, not “moved”. Two
things other than a move put a vehicle in it:

- **A vehicle not located in the comparison year** (`unknown`) is
  counted as `different`, not as missing. This is rare: 33,656 vehicles
  arrived in an area in 2018 from `unknown` or `dead`.
- **In Sets 1b and 1c a new vehicle is `different`.** The status
  describes the later year against the earlier one, so a vehicle that
  was `unborn` a year earlier and is now in an area is `different` - it
  did not move, it was registered. In 2018, 2.57M of the 8.57M
  `different` vehicles in Set 1b (lag 1) were new vehicles; 5.97M had
  moved from another area. **Set 1d** separates these flows; use it for
  any statement about moving.

**A move** - a change of postcode area between two consecutive years
where **both** years hold a real postcode area. A vehicle going LS →
`unknown` → BD is recorded as **no moves**, because neither pair of
consecutive years has two real areas. This makes the move counts
conservative: real moves across a gap in observation are not counted.

**Age** - whole years at 1 June of the year in question, calculated as
the days from the first use date to 1 June divided by 365.25, rounded
down. A vehicle first used in August 2013 is age 3 in 2017, not 4. Ages
can be negative (a first use date after the year), which is why the age
bands include a `<0` band.

**Movement rate** - the churn v2 definition,
`n_moves_2007_2017 / (age in 2017 - 3)`, defined for vehicles aged 4 or
over in 2017. The idea was “moves per year of life after the first
three, when a car has no MOT”. It does not measure that, for two
reasons, and **it should not be compared across ages**:

- The annualisation back-fills a vehicle’s postcode area into the years
  before its first MOT, so those years are “located” and a move between
  them can be counted (though, being copies, they rarely show one). The
  numerator therefore counts moves over up to ten year pairs (2007-2017)
  while the denominator counts years of life after the third.
- For a vehicle aged 4 the denominator is 1 but there are about 4.5
  observed year pairs; for a vehicle aged 20 it is 17 but there are at
  most 10.

In this build the mean churn v2 rate falls from 0.47 at age 4 to 0.05 at
age 20 and over, while the windowed rate stays between 0.1 and 0.2 at
every age: the fall is produced by the formula, not by the vehicles. The
churn v2 rate is larger than the windowed rate below age 13 and smaller
above it. **Windowed movement rate** divides by the number of year pairs
where both years hold a real area
(`n_moves_2007_2017 / n_obs_2007_2017`), so it measures moves per
observed year and is the one to quote. Note that the observed pairs
include the back-filled years before the first MOT and the two years
after the last one, in which no move can appear, so even the windowed
rate understates the rate at which vehicles that are on the road change
area.

**Static** - a vehicle in a real postcode area in 2017 that was in the
*same* area in 2016 and 2018. A vehicle `unknown` in 2016 is therefore
not static, even if it never moved: non-static mixes movers with
vehicles not located in 2016 or 2018 (or dead by 2018). Of the 2017
cohort aged 4+, 64.8% were static.

**Bands** - every band includes its lower bound and excludes its upper
bound. Engine size 2000cc falls in `1700-2000`; 2001cc falls in `>2000`.
Mileage 12,000 falls in `>12k`, not `5-12k`. Engine size 0 has a band of
its own, 0 (electric), because the harmonised engine size is 0 for the
fuels with no engine; the lowest size band starts at 1cc and says so.

**The `NA` column** - several wide tables have a final column headed
`NA`. That is not an error: it counts vehicles whose characteristic is
unknown (usually engine size or mileage). Tables that list one row per
category instead *drop* the unknown category. So a band table and its
matching cross-tab can have slightly different totals, and the
difference is the unknowns.

**Zeros** - every combination of area, year and band appears in the wide
tables, filled with 0 where no vehicle matched. A 0 means “none”, not
“not measured”.

**Rounding** - counts are exact. Proportions in Sets 2 and 6 are written
at full precision. Average mileages in Set 7 are rounded to one decimal
place; percentages in Set 0 to two.

## 6. How complete the variables are

The table in section 4.1 gives the exact missing counts. In words, for
the 81,112,156 vehicles:

- **Location and fuel are never missing.** Every vehicle has a value in
  every `pca_YYYY` column (though 49.0% of 2017’s values are one of the
  three stand-in words), and every vehicle has a fuel group.
- **Engine size** is missing for 6,232 vehicles (0.0%), so the four
  engine band columns are missing for exactly the same vehicles.
- **Euro status** is missing for 3,888,410 vehicles (4.8%); in the
  harmonised column these hold the reason instead (`pre_euro`,
  `no_schedule` or `no_date`), so count them by `euro_status_src`, not
  by an empty `euro_status`. That looks like good coverage, but most of
  it is an assumption rather than a record: the register holds a Euro
  status for only a minority of vehicles, and where it holds none the
  enhanced table fills in the standard that was compulsory for new
  registrations of that body type when the vehicle was made
  (methodology.md, Section 5.7). Euro status is used only in Set 7,
  where it decides the Clean Air Zone category together with the first
  use date.
- **Movement rate** is missing for 30,878,242 vehicles (38.1%) - those
  aged under 4 in 2017, for whom it is not defined.
- **`birth_pca`** (the area a vehicle first appeared in) is missing for
  41,617,674 vehicles (51.3%): vehicles already registered before the
  data starts never have an `unborn`-to-area transition to read it from.
  Set 4’s “born here” columns are only meaningful for recent vehicles.
- **The dates behind the age calculation** are never missing in the
  combined `first_use_date`, but the individual sources are: DVSA’s own
  date is missing for 10,093,594 vehicles (12.4%), which is what Set 0
  reports on.

## 9. The tables, one set at a time

Each set below says: the question, the vehicles counted, the variables,
the grouping, the arithmetic, and the files, and ends with graphs drawn
from its CSVs in `outputs/tables/churn/` as written by this build. A map
of a table that covers every year shows 2022, the latest year whose
fleet is complete (vehicles first tested in the most recent years are
not all back-filled yet); grey areas have no vehicles in the table.

### Set 0 - where the first use date came from

- **Question.** How much of the age calculation rests on DVSA’s own
  date?
- **Vehicles.** All 81,112,156.
- **Variables.** `firstUsedDate_DVSA`, `monthOfFirstRegistration_DVLA`,
  `birth_date`.
- **Grouping.** None. Four counts, one per source, by the first rule
  that applies: DVSA’s date if present, else DVLA’s first registration,
  else `birth_date`, else none.
- **Arithmetic.** `pct` is the count over all vehicles, to two decimals.
  `n_differs_from_v1_birthDate`, on the first row only, counts vehicles
  whose DVSA first use date is not the same day as `birth_date` - a
  measure of how much the earlier version of this analysis, which used
  `birth_date`, differed.
- **File.** `set0_first_use_date_provenance.csv`.

### Set 1 - who is still where they were

- **Question.** Of the vehicles in area X in a reference year, how many
  are in the same area, a different one, dead or not yet born, in each
  later year?
- **Vehicles.** All of them, including those whose reference-year
  location is `dead`, `unborn` or `unknown` - except in `set1a2`, which
  keeps only vehicles in a real area in 2017 (41,341,397 vehicles).
- **Variables.** `pca_YYYY` for every year, `test_class`, and age for
  the `age4plus` variants.
- **Grouping.** Row = reference-year postcode area (plus test class).
  For each year, every vehicle is labelled `same`, `different`, `dead`
  or `unborn` against the reference year, and the labels are counted.
- **Arithmetic.** Counts only. The table is then pivoted so each
  status-and-year pair becomes a column, named `status_year` (for
  example `same_2019`), ordered by year then status, with missing
  combinations as 0.
- **Files and what the reference year is.**
  - `set1a_...change_from_2017.csv` - reference year 2017, all vehicles.
    Rows include `dead`, `unborn` and `unknown` as reference locations.
  - `set1a2_..._cohort_only.csv` - the same, restricted to vehicles in a
    real area in 2017. This is the one to use for “of the 2017 fleet,
    how many stayed”.
  - `set1b_...from_year-N.csv` for N = 1, 2, 3 - a rolling comparison:
    each year against the area N years earlier. The row label is the
    **later** year’s area, so a vehicle contributes to different rows in
    different years.
  - `set1c_...from_year-N_age4plus.csv` for N = 1, 2 - as 1b, but only
    vehicles aged 4 or over in the later year, which removes the
    cars-with-no-MOT-yet effect.
  - `set1d_pca_flows_year-1.csv` - the year-on-year flows behind 1b (lag
    1), one row per year and area: `stock_prev` (in the area a year
    earlier), `stayed`, `out_moved` (now in another area), `out_dead`,
    `out_unobserved`, `in_moved` (from another area), `in_new` (unborn a
    year earlier), `in_reappeared` (unknown or dead a year earlier) and

    nationally, `in_moved` equals `out_moved`. Added in the October 2026
    audit.

  new vehicles (section 5): 1b’s `different` is not a count of movers -
  Set 1d’s `in_moved` is. The `test_class` column is constant (4)
  because of the class filter; it is kept so the file shape matches the
  earlier analysis.

### Set 7 - Clean Air Zone categories, leavers and stayers

- **Question.** Where are the vehicles a Clean Air Zone or the ULEZ
  would charge, and do they leave the area or stay?
- **Rows.** Every postcode area (`geography = pca`), plus three groups
  (`geography = group`):
  - Inner London (E N NW SE SW W)
  - Outer London (BR CR EN HA IG RM SM TW UB)
  - All other: every other area, apart from the areas partly in London,
    the clean air zone areas and BT XX

  Some areas are repeated straight after the London groups:
  - the areas partly in Greater London (KT, DA, WD,
    `geography = partial_london_pca`)
  - each area with a charging clean air zone (BA, B, PO, OX, BD, BS, NE,
    S, G, `geography = caz_pca`)

  These areas belong to no group. `set7_area_definitions.csv` lists the
  schemes, their class and when charging started, and the config `set7`
  section holds the lists. **Sum the `pca` rows only**; the other rows
  group or repeat them.
- **Vehicles.** In each year from 2018 to 2023, the vehicles in a real
  area. 7B and 7C start from the vehicles in a real area in 2018
  (42,034,312).
- **Variables.** `caz_status` is worked out in Set 7 from fuel, first
  use year and the Euro standard. Both conditions of the charging rule
  must hold:
  - **petrol** first used before 2006 and not Euro 4 or later →
    `petrol_pre2006_not_euro4`
  - **diesel** first used before 2015 and not Euro 6 or later →
    `diesel_pre2015_not_euro6`
  - everything else → `other`

  A vehicle with no Euro standard (`pre_euro`, `no_schedule`, or none)
  is placed by its date alone. Mileage is annual mileage, averaged only
  over the vehicles that have one.
- **Present.** A vehicle counts as “present” in 2023 if it is still in
  the same row: the same area for an area row, or anywhere in the group
  for a group row. A move from E to N therefore stays in Inner London,
  and a move from LS to M stays in All other. As a result, the group
  rows of 7B and 7C are not the sums of their area rows.
- **Files.**
  - `set7a_pca_caz_categories.csv` and its long form
    `set7a_pca_caz_category_by_year_long.csv` - counts and average
    mileage by row, category and year, with `total_vehicles_YYYY`. The
    wide file also has the vehicles present in the row in both 2018
    and 2023. The long form gives the count behind each average
    (`n_with_mileage`).
  - `set7b_leavers_2018_to_2023.csv` - vehicles in the row in 2018 that
    are **not in it** in 2023 (26,793,137 over the area rows, 63.7% of
    the 2018 stock). For each category: the count and the average
    mileage in 2018 and in 2023 for all leavers, then the same split by
    where the leaver was in 2023:
    - `moved`: in another area and still running
    - `dead`: scrapped
    - `unknown`: not located

    The column names are `n_moved_*`, `n_dead_*`, `n_unknown_*` and
    `avg_mileage_YYYY_{outcome}_*`.
  - `set7c_stayers_2018_to_2023.csv` - the same for vehicles in the row
    in both years. In each row, 7B + 7C is the 7A 2018 total.
  - `set7b_..._by_breakdown_long.csv` and
    `set7c_..._by_breakdown_long.csv` - the same measures by category
    and by each of these 2018 characteristics:
    - mileage band (with a `no mileage` band)
    - engine size in four bands
    - fuel (Petrol, Diesel, Electric, Hybrid, Other)
    - age band

    The `all` breakdown is the whole row, and every other breakdown adds
    up to it. In 7B every line is also split by `outcome_2023` (`all`,
    `moved`, `dead`, `unknown`). Only combinations with vehicles are
    listed.
  - `set7_check_caz_status_change.csv` - how the Euro condition changes
    the date-only category, by where the Euro status came from. Of the
    7,833,289 petrol vehicles first used before 2006, 416,641 are Euro 4
    or later and move to `other`. Of the 13,376,907 diesels first used
    before 2015, 764,407 are Euro 6 and move. Almost all of these moves
    rest on a recorded or borrowed standard. Where the standard was
    assumed from the date (`euro_schedule`), the Euro condition repeats
    the date test and moves almost nothing. The categories therefore
    partly reflect which vehicles have a recorded standard.
  - `set7_check_caz_category_vs_eurostatus.csv` and
    `set7_check_caz_proxy_agreement_by_source.csv` - checks of the
    date-only proxy (`caz_cat`) against the Euro standard. Only `dvla`
    (recorded on the vehicle) and `variant` / `model_year_fuel` (the
    recorded value of similar vehicles) test the proxy independently. Of
    the `petrol_pre2006` cars with one of those standards, only 8.4% are
    below Euro 4; for `diesel_pre2015` the figure is 76.5%.
- **Traps.**
  - “Leaver” includes vehicles that were scrapped and vehicles not
    located in
    2023. The `moved` / `dead` / `unknown` split separates them. A
          scrapped leaver seldom has a 2023 mileage, so the all-leaver
          `avg_mileage_2023` mostly describes the leavers still running
          elsewhere; use the `moved` columns for those.
  - Postcode areas do not follow the Greater London boundary, and a zone
    covers only part of its area (B includes Solihull, for example).
  - Class B and C zones do not charge private cars.
  - Most zones began charging in 2021-2023, so there are few years after
    the start.

## 11. How to rebuild this

The churn tables and this document are built by the pipeline, so they
always describe the same run:

    # everything
    targets::tar_make()

    # just the churn tables and this document
    targets::tar_make(names = tidyselect::starts_with("churn"))

Changing a setting under `churn:` in `config.yml` rebuilds the tables
that depend on it and then this document. Editing the band definitions
or the documentation text means editing `R/summary_churn.R`,
`R/report_churn.R` or `reports/churn_tables_report.qmd` - never the
generated `.md` file, which is overwritten on every run.

## 12. Things to be careful about, in one place

1.  **`different` includes `unknown`.** In Set 1 and among Set 7B’s
    leavers, a vehicle that was simply not seen counts as not being in
    the same place (Set 7B shows these separately as `unknown`).
2.  **Moves are only counted between two observed years.** A move across
    a gap in observation is invisible, so move counts and movement rates
    are floors, not estimates.
3.  **A location is not always an observation.** A car under three has
    no MOT, and the annualisation copies its first test’s postcode area
    back to its first registration; after the last MOT, the area is
    carried on for two years before the vehicle becomes `dead`. So a
    young vehicle cannot be seen to move before its first test, and a
    scrapped vehicle stays in its area’s stock for about two years.
    Against DfT’s licensed + SORN counts, the cars aged 3+ located in a
    postcode area are 6-19% too many, depending on the year (data
    quality report, cross-checks). The last two or three years of data
    are also incomplete, because recent first tests are not yet
    back-filled.
4.  **`movement_rate` (churn v2) falls with age by construction.** Use
    the windowed rate for any comparison across ages or characteristics
    (section 5).
5.  **Set 1b’s `different` includes new vehicles**, about 30% of it in a
    typical year. Use Set 1d’s `in_moved` and `out_moved` for moves.
6.  **Sets 2 part 2, 3 and 6 are about a 2017 cohort** (36.1% to 51.0%
    of all vehicles, depending on the table). They say nothing about
    vehicles that arrived afterwards.
7.  **Unknown characteristics are handled two ways.** Wide tables put
    them in an `NA` column; per-category tables drop them. Totals
    between the two differ by exactly that amount.
8.  **Averages skip missing values rather than treating them as zero.**
    An average mileage is over vehicles with a recorded mileage; divide
    the count columns yourself if you want a per-vehicle figure over
    everybody.
9.  **Northern Ireland is one area, `BT`.** It is included unless
    `exclude_ni_rows` is `TRUE` (currently FALSE). Tables built before
    October 2026 called it `NI`.
10. **The row label in Set 1b and 1c is the later year’s area**, not the
    earlier one, so the same vehicle can appear under different areas in
    different columns of one row-set.
11. **Most Euro statuses are assumed, not recorded.** A missing Euro
    status is filled from the date the vehicle was made, so the Set 7
    Euro check compares a date-based category with a largely date-based
    standard.
12. **The fuel groups now separate plug-in hybrids.**
    `Plug-in Hybrid Electric` is a sixth fuel group, taken from the DfT
    licensing statistics for the vehicle’s model (methodology.md,
    Section 5.5). It is a floor: a plug-in hybrid of a model DfT sells
    both ways, and whose model text did not settle it, still counts as
    `Hybrid Electric`. In churn v2 mode (`churn.fuel_column` =
    `fuel_DVSA`) the group is always empty, because the DVSA fuel does
    not have it.
