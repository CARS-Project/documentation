Appendix C — Maintaining this book

This appendix is for the people who maintain the book. It explains how the numbers, tables and figures that come from the data pipeline are kept up to date.

C.1 The build this edition describes

C.2 How data gets into the book

Nothing in the book reads the pipeline repository directly. Instead:

  1. data/manifest.yml lists every file the book uses from MOT-pipline.
  2. scripts/sync-pipeline.R copies those files into data/pipeline/ (data) and reports/ (the pipeline’s reports, shown as appendices), and records the pipeline’s commit in data/pipeline/provenance.csv.
  3. scripts/run-examples.R runs each query in sql/ against the vehicle table and saves the result in data/examples/. The worked examples display the same .sql files, so the code shown is exactly the code that produced the results.
  4. scripts/run-coverage.R counts, for every column of the vehicle table, how many vehicles have a value, by year of first use and by year, and saves the counts in data/coverage/ for the coverage sections of the data dictionary. scripts/run-values.R likewise summarises each column’s values over time, in data/values/, for the dictionary’s Values sections.
  5. Chapters read the copies with read_pipeline() and read_example() from R/book.R, and compute every number, table and chart from them when the book is rendered.

The copies are committed, so anyone can rebuild the book without access to the pipeline or the 9 GB vehicle table.

C.3 Updating after a new pipeline build

From the book’s root folder, with MOT-pipline checked out alongside it (or MOT_PIPELINE_DIR set to its location):

Rscript scripts/sync-pipeline.R   # copy the new outputs
Rscript scripts/run-examples.R    # rerun the examples (needs the parquet)
Rscript scripts/run-coverage.R    # recount column coverage (needs the parquet)
Rscript scripts/run-values.R      # resummarise column values (needs the parquet)
Rscript scripts/rebuild.R         # re-execute every chapter and render

Then check the result, and commit data/, reports/ and _freeze/. Pushing to main publishes the book.

ImportantCheck the words, not just the numbers

Numbers in the text are computed, but sentences that interpret them (“the two averages are almost identical”, “most were still tested in Leeds”) are written by hand. After a rebuild, read the chapters whose figures changed and make sure the text still fits.

If a pipeline file used by the book is renamed or removed, the sync script stops with an error naming it. Update data/manifest.yml and the chapter that reads it.

C.4 Why rebuild.R clears the frozen results

The book uses Quarto’s freeze option: the results of each chapter’s code are stored in _freeze/ and reused until that chapter’s source changes. This is what lets GitHub Actions publish the book without R. It also means a plain quarto render will not pick up new data, because the chapters themselves have not changed. scripts/rebuild.R deletes _freeze/ so that every chapter runs again.

C.5 Adding pipeline data to a chapter

  1. Add the file to data/manifest.yml.
  2. Run Rscript scripts/sync-pipeline.R.
  3. In the chapter, source("R/book.R") and read it with read_pipeline("outputs", "tables", ...).

To add a worked example, put the query in sql/ (naming the file as 'vehicles_enhanced.parquet'), run Rscript scripts/run-examples.R exNN, and show it with {{< include ../sql/exNN_name.sql >}} inside a sql code block.

C.6 When the vehicle table gains or loses columns

The data dictionary chapters (chapters/dictionary/) each describe a group of columns, defined once in dict_groups in R/book.R. A column that has been removed stops the render with an error naming it. A new column is listed in a warning on the part’s opening page until it is added to a group, and to that chapter’s overview text. Rerun scripts/run-coverage.R and scripts/run-values.R after either change. A column whose values should be charted as categories although it is stored as a number belongs in dict_coded.

C.7 Writing conventions

  • Placeholders for material still to come are callouts titled To be written (or To be confirmed for statements to check), with the class .todo. Search the chapters for .todo to list them.
  • Pitfalls are callouts titled Pitfall: …, and each is also summarised in
  • Charts use theme_cars() and the palette in R/book.R, with at most four series each.

C.8 Publishing

.github/workflows/publish.yml renders the book from the frozen results and publishes it to the gh-pages branch on every push to main. One-off set-up: run quarto publish gh-pages once locally to create the branch, then in the repository’s settings set GitHub Pages to deploy from the gh-pages branch. The book will then be at cars-project.github.io/documentation.

To preview locally, run quarto preview.
